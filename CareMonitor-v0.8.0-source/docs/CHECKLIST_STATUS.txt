1. TWO CLASSIFIERS ON THE SAME TASK — IMPLEMENTED AND EVALUATED OFFLINE
Decision Tree and Random Forest were compared on each of the same four supplied
binary synthetic-vitals tasks, using the exact previously recorded partitions:
35,993 training, 12,005 validation and 12,002 held-out test rows. Hyperparameters
and family selection use validation macro-F1, not the test set. Ties select the
simpler Decision Tree. Both selected families scored 1.0 held-out macro-F1 on
these deterministic synthetic labels. This does not establish real-sensor or
clinical accuracy.
Evidence: evidence/ml/metrics.json, comparison.csv, split_manifest.json,
split_membership.csv and the four confusion-matrix figures.

2. CLASSIFICATION + CONFIDENCE JSON ENDPOINT — IMPLEMENTED IN CANDIDATE
POST /ml/classify requires HTTPS, a sensor:read API credential and matching
device_id. It returns NORMAL/ABNORMAL, numeric confidence, class probabilities,

NEW FALL-RESPONSE REQUIREMENT
The candidate adds a possible-fall response state machine with a persisted
deadline 15 seconds after detected_at, not 15 seconds after polling or receipt.
The wearer can cancel before the deadline; expiry escalates, and Help now
bypasses the remaining delay. Cancellation/escalation and duplicate suppression
are transactional. A worker checks due deadlines approximately every 250 ms.
The accepted sources are explicitly manual_test and wearer_help; there is no
validated live fall detector and no physical fall trial. The server queues
assigned-caregiver inbox records, but push_configured remains false. An
authenticated /seen acknowledgement means the caregiver client reported seeing
the record; queueing alone is not delivery.
Still required: Android countdown/cancel/help integration, a configured push
transport such as FCM, delivery acknowledgements, network/restart/phone tests,
and appropriate source timing. A correctly synchronised server clock and a
reachable server are assumptions. A 250 ms sweep is not a guarantee of immediate
delivery. Missing-caregiver status is explicit; still-open events backfill their outbox when a caregiver is assigned. A database trigger blocks patient reassignment until an incident is closed.
Evidence: fall_events.py, fall_routes.py, candidate_app.py and associated tests.
