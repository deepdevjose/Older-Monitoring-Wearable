\subsection{Installation and execution procedure}
The current APK and source archive are distributed under \path{release/}. The application is version 1.0.0, code \CurrentVersionCode{}, minimum API 24 and target API 37. Its SHA-256 is \expandafter\nolinkurl\expandafter{\CurrentApkHash}. Device execution was recorded as follows: \CurrentAndroidResult. The older report snapshots retain code 13's separate installation and 709-check campaign. The operational guides are \path{docs/SERVER.md} and \path{docs/PUESTA_EN_MARCHA.md}; use the exact endpoint and device identity for the selected transport.
\begin{enumerate}
\item Prepare the Python environment from \path{requirements.txt}; initialise the local server using \code{./carectl init --host YOUR_LAN_IP}. Keep generated keys private.
\item Use \code{./carectl start} and \code{./carectl status} to check HTTPS service readiness. Ensure the public CA bundled in the APK matches that server. Follow \path{docs/SERVER.md} when regenerating a build.
\item Install \path{release/CareMonitor-1.0.0.apk} using Android's authorised local installation flow and retain its hash and device identity. The installation, preview and isolated system campaigns used S22 Android 13/API 33. Preview fixtures do not grant permissions or activate sensors; the separate system campaign exercises actual acquisition and HTTPS.
\item Use fictional adult and caregiver accounts for server experiments. Registration presents role, name, email and password as separate steps; the adult issues an invitation and approves the caregiver request. The server enforces that relationship.
\item Run \code{./carectl demo} with fictional adult credentials. This sends three synthetic rule samples; verify one episode and independent caregiver review. Rule episodes are separate from saved model exercises.
\item Tap a metric card and select Day, Week or Month. Inspect the range, chart, units, gaps and coverage statement. In caregiver mode, select an approved adult and check the same authorised history. A missing current reading must not hide retained history.
\item Open Settings, then Learning insights. Under a fictional adult account choose each synthetic CSV example, inspect the three features, then classify and save. Verify class, score and timestamp in Recent exercises. The approved caregiver can read the same history but cannot submit for the adult. The original \path{/api/v1/ai/classify} remains a separate stateless API.
\item Reproduce interface checks only in an isolated preview or on a test device. Use the exact serial, preserve real accounts and retain the active-session guard. Fictional fixture results do not establish backend or Bluetooth operation.
\end{enumerate}

\subsection{Application latency and improvement protocol}
Select an initial revision and an improved revision before the experiment. Use the same device, dataset fixture IDs, server hardware, network and permissions. After identical warmup, record at least thirty trials per scenario. Measure API time from dispatch to parsed response, and caregiver latency from the first qualifying synthetic input to visible notification. Keep raw timestamps, request IDs, failed trials and timeouts. Report N, mean, p50 and p95 for both revisions; do not silently omit failed deliveries.

For missed Critical alerts, divide Critical scenarios without a required visible alert within the declared observation window by all Critical scenarios that should generate one. For false Warnings, divide Normal scenarios producing an unwanted Warning by all Normal scenarios. Define the observation window before testing. Model predictions and rule alerts have different semantics; a latency experiment must identify the rule output and its observation window. Separately report duplicates and data loss after reconnection.

\section{Demonstration evidence and evaluation boundaries}
\label{app:acceptance}
The completed evaluation combines native interface checks, synthetic model/rule experiments and an integrated physical bench campaign. Their records retain separate versions and execution boundaries rather than treating every test as a single deployment.

The installed production code \CurrentVersionCode{} has a verified APK identity, authenticated SPP reception and HTTPS storage. Its existing account was preserved. The current isolated screen campaign adds 305 checks and 83 unique native images from 89 capture operations; its forms were captured before submission. A separate preview ran 7,198 assertions and captured 48 views at normal/enlarged text. The earlier 709-check onboarding result retains code 13's identity.

The 30 October system campaign used production Java/resources in an isolated application ID with controlled accounts, real Bluetooth SPP and HTTPS. It verified caregiver request and adult approval, retained 76 physical readings, reached zero pending uploads and rendered both roles from actual API responses. Learning insights saved Normal, Warning and Critical synthetic exercises. Final notification trials posted 30/30 native caregiver notices within ten seconds after the bounded-window correction. The following subsections retain the earlier observation chain and timing. Appendix~\ref{app:mobile-screens} contains the current role-separated screenshots and task explanations.\cite{systemrun}

To reproduce the integrated path:
\begin{enumerate}
\item Follow Appendix~\ref{app:repro} to prepare the trusted local server and exact APK/endpoint. Record device, build and transport identities before the run.
\item Use controlled adult/caregiver accounts. Connect the adult's wearable, then request and approve the care relationship; verify retained readings and the upload queue before opening caregiver views.
\item Tap a metric card to fetch retained history, and separately classify/save the synthetic learning examples. Capture the selected person's native views with the corresponding server record and source identity.
\item Repeat notification trials using the declared screen state, observation window and permissions. Retain every successful post and timeout; do not substitute model accuracy or server-only timings for delivery results.
\end{enumerate}
