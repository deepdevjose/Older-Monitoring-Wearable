CURRENT OBSERVED FAILURE
The phone-to-server upload and SQLite storage are working. Over 43.925 seconds,
45 real uploaded frames had valid acceleration XYZ, but all 45 optical frames
reported read_error, sample_count=0, calculation_count=0, and no valid HR/SpO2.
Reported hardware overflow events increased by 20,749 (about 472 per second).
These are firmware-reported counts; they do not prove actual physical sample loss.
See diagnostics/checked-direct-server-receipt-20261023.json and the sanitized
serial startup report. No simulated records were inserted for this evidence.

FIRST CODE AREA TO REVIEW
PpgFifoReader.h: the overflow != 0 branch. It writes FIFO_RD_PTR (0x06) and
OVF_COUNTER (0x05), treats ACK as recovery, clears its software latch and
returns without consuming a FIFO sample. If the device still reports a nonzero
overflow field, every later loop repeats that branch and no samples reach the
100-sample calculation window. This is the leading hypothesis, not yet a
hardware-verified fix. The fake-bus tests model the overflow write as clearing
its counter; passing them did not establish that effect on the real device.
